Login with Muse — one-button ES256 key generator

Tap one button. The key pair is generated in this browser only — nothing is sent anywhere, and no code needs to be pasted into a console.

Keep the private key private. Never post it, never send it in a chat, never paste it anywhere except the one Cloudflare secret below. If it leaks, generate a fresh pair and replace both values.

1 — Public key (copy this)

Paste this whole JSON object into Cloudflare as a plain variable named SIGNING_PUBLIC_JWK.

2 — Private key (copy this, keep it secret)

Paste this whole JSON object into Cloudflare as an encrypted secret named SIGNING_KEY_JWK.

3 — Admin token (optional helper)

This is not part of the key pair. It is the long random password for ADMIN_TOKEN. You can use your own instead. Paste the value you choose into Cloudflare as an encrypted secret named ADMIN_TOKEN, and keep a copy of it somewhere safe — it is needed for the client-registration step.

What to paste where — in order

  1. Open the Cloudflare dashboard for the museai-oauth2 worker.
  2. Plain variable: SIGNING_PUBLIC_JWK = the public key JSON from box 1.
  3. Encrypted secret: SIGNING_KEY_JWK = the private key JSON from box 2.
  4. Encrypted secret: ADMIN_TOKEN = a long random password you pick (or the one from box 3).
  5. Save / redeploy the worker from the dashboard, then check the live verification step below.

After the key exists — what is left to finish login

  1. Verify live (Muse): discovery must return the issuer https://fedpromptly.com/login plus endpoints (not not_configured), and JWKS must serve the public key. Worker health is at https://museai-oauth2.fedos.workers.dev/login/health (note: root /health 404s because BASE_PATH=/login — that is expected).
  2. Register first client(s) + Muse key(s) (Muse, with ADMIN_TOKEN): POST /admin/clients and POST /admin/muse-keys. Registries are empty until this step — no real login works before it.
  3. Full live sign-in proof (Muse): authorize flow + device flow + deny + rate limit + kill switch against the deployed worker. Acceptance test: signing in must hand back the user's email every time.
  4. Attach login buttons (Git-FED's step, then Muse checks): his own sites first, then everything he ever created. Each site needs its own login snippet — a snippet works only for the site it was registered for.
